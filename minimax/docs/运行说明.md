# 运行说明

本文说明如何在干净环境中安装依赖、初始化数据、启动模块并执行验证样例。

## 1. 环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Python | 3.11+ | 模块与业务工程都运行在 Python 3.11 及以上 |
| uv | 0.12+ | 用于创建虚拟环境与安装依赖 |
| PowerContext Server | 1.4.1 | 保存任务状态，通过 HTTP API 访问 |
| MiniMax API | — | 通过 Messages API 参与代码修改 |
| seekDB | 1.4.0.post2 | 嵌入式实例，随 `pylibseekdb` 一起安装，无需单独部署服务 |

嵌入式 seekDB 使用 `pylibseekdb` 的 wheel。Windows、macOS 与 Linux 都有对应 wheel，
数据库目录由模块自行创建，进程重启后可以再次打开并读到之前写入的资料。

## 2. 安装

在仓库的 `minimax/` 目录下执行：

```bash
# 上下文模块及其依赖（嵌入式 seekDB、PyMySQL）
python -m venv .venv
.venv/bin/python -m pip install -e .

# 样例业务工程及其测试依赖
python -m venv demo_shop/.venv
demo_shop/.venv/bin/python -m pip install -e demo_shop
demo_shop/.venv/bin/python -m pip install pytest
```

Windows 下使用 `.venv\Scripts\python.exe` 与 `demo_shop\.venv\Scripts\python.exe`。

## 3. 配置

模块从环境变量读取配置，全部使用占位值，不提交真实凭据：

```bash
# PowerContext Server
export SDDCTX_POWERCONTEXT_URL=http://127.0.0.1:8000
export SDDCTX_SCOPE_ID=sdd-context-demo          # 逻辑名称，作为幂等键使用
export SDDCTX_POWERCONTEXT_TOKEN=<可选的访问令牌>

# 嵌入式 seekDB 的数据目录，默认 <minimax>/.sddctx/seekdb
export SDDCTX_DB_DIR=<minimax>/.sddctx/seekdb

# MiniMax
export MINIMAX_BASE_URL=https://api.minimax.chat/v1
export MINIMAX_MODEL=MiniMax-M2.7
export MINIMAX_API_KEY=<你的 MiniMax API Key>

# 项目根目录，默认当前工作目录
export SDDCTX_ROOT=<minimax 目录>
```

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `SDDCTX_ROOT` | 项目根目录，决定 `specs/` 与 `demo_shop/` 的位置 | 当前工作目录 |
| `SDDCTX_DB_DIR` | 嵌入式 seekDB 数据目录 | `<root>/.sddctx/seekdb` |
| `SDDCTX_POWERCONTEXT_URL` | PowerContext Server 地址 | `http://127.0.0.1:8000` |
| `SDDCTX_SCOPE_ID` | 保存任务状态的 Scope 逻辑名称 | `sdd-context-demo` |
| `SDDCTX_POWERCONTEXT_TOKEN` | 启用鉴权时的 Bearer 令牌 | 空 |
| `MINIMAX_BASE_URL` | MiniMax Messages API 地址 | 见上表 |
| `MINIMAX_MODEL` | 参与代码修改的模型 | `MiniMax-M2.7` |
| `MINIMAX_API_KEY` | MiniMax 凭据 | 空 |
| `MINIMAX_TIMEOUT` | 单次请求超时（秒） | `180` |

## 4. 启动 PowerContext Server

模块把任务状态写入 PowerContext Server，因此先启动 Server：

```bash
uv tool install --force "powercontext[cli,server]==1.4.1"
powercontext server run
```

Server 默认监听 `127.0.0.1:8000`，在操作系统用户数据目录中创建持久化 SQLite 数据库，
并在 `/mcp` 暴露 Streamable HTTP MCP。本模块只使用 HTTP API，不依赖 MCP。

验证 Server 是否就绪：

```bash
curl http://127.0.0.1:8000/health/live
```

## 5. 调用入口

模块的入口是命令行：`python -m sddctx <子命令>`（安装后也可直接使用 `sddctx`）。

| 子命令 | 作用 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| `import` | 把规格、代码符号与测试导入 seekDB | `--specs`、`--project` | JSON 摘要（导入条数、发生变化的规格） |
| `context` | 检索并组装开发上下文 | `--task`、`--task-id` | 文本或 JSON（规格、代码、测试、复用的状态） |
| `apply` | 交给 MiniMax 修改代码并执行测试 | `--task`、`--task-id`、`--tests` | 变更文件、测试退出码、技术记录 |
| `state save` | 把任务状态写入 PowerContext | `--file` | JSON（写入的 Source id） |
| `state show` | 从 PowerContext 读回任务状态 | `--task-id` | JSON（目标、事实、已完成、待办、校验结果） |
| `run` | 执行完整流程 | 同 `apply` | 同 `apply` |

输入输出的完整说明见 [`../docs/验证样例.md`](../docs/验证样例.md)。

常用示例：

```bash
# 导入资料
python -m sddctx import

# 查看某个任务的开发上下文
python -m sddctx context \
  --task "为订单筛选增加客户等级分组过滤：customer_tiers 中的 premium 分组必须展开为 gold 与 silver" \
  --task-id task-filter-003

# 让 MiniMax 修改代码并执行测试
python -m sddctx apply \
  --task "为订单筛选增加客户等级分组过滤：customer_tiers 中的 premium 分组必须展开为 gold 与 silver" \
  --task-id task-filter-003 \
  --project demo_shop \
  --python demo_shop/.venv/bin/python \
  --tests tests/test_filters_tier_groups.py

# 读回任务状态
python -m sddctx state show --task-id task-filter-003
```

## 6. 执行验证样例

```bash
python verify/run_verification.py
```

脚本会依次执行九步，并把每一步的命令、退出码和输出写入 `artifacts/logs/`：

| 步骤 | 内容 | 期望退出码 |
| --- | --- | --- |
| 0 | 把业务代码还原到修改前���状态 | 0 |
| 1 | 导入资料到 seekDB | 0 |
| 2 | 组装开发上下文 | 0 |
| 3 | 修改前执行目标测试与回归测试 | 目标测试非 0，回归测试 0 |
| 4 | 由 MiniMax 修改代码并应用差异 | 0 |
| 5 | 修改后执行同一组测试 | 均为 0 |
| 6 | 从 PowerContext 读回任务状态 | 0 |
| 7 | 重启模块，用复用的状态重新组装上下文 | 0 |
| 8 | 更新规格、重新导入、确认上下文使用更新后的内容 | 0 |
| 9 | 记录 seekDB 查询与 PowerContext 状态 | 0 |

脚本最后打印七项检查，全部为 `PASS` 时退出码为 0。

## 7. 测试命令

```bash
# 上下文模块自身的测试
.venv/bin/python -m pytest tests -q

# 业务工程的目标测试
demo_shop/.venv/bin/python -m pytest tests/test_filters_tier_groups.py -v

# 业务工程的回归测试
demo_shop/.venv/bin/python -m pytest tests/test_filters_regression.py tests/test_pricing.py -v
```

## 8. 重置方法

| 需要重置的内容 | 方法 |
| --- | --- |
| 业务代码 | `python verify/reset_code.py`，把 `artifacts/code-snapshot-before/` 复制回 `demo_shop/` |
| 规格 | `python verify/apply_spec_update.py --reset`，恢复 `specs/SPEC-FILTER-003.md` 的基线版本 |
| seekDB 中的资料 | 删除 `SDDCTX_DB_DIR` 指向的目录后重新执行 `python -m sddctx import` |
| PowerContext 中的状态 | 停止 Server 后删除其用户数据目录中的 SQLite 数据库，再重新启动 Server |

## 9. 已知限制

- PowerContext 的官方文档把 Windows 标记为 `experimental`。本模块在 Windows 上完成了验证，
  但官方推荐 macOS 与 Linux。
- 嵌入式 seekDB 的全文索引按空白分词，中文短语无法命中 `MATCH ... AGAINST`。
  模块因此对中文使用 `LIKE` 匹配、对标识符使用全文索引，两种信号合并后排序。
- 模型返回的 unified diff 的行号可能与文件不一致。模块会按上下文块在文件附近定位，
  上下文对不上时拒绝写入，不会留下半应用的文件。
- 模块使用 `MATCH ... AGAINST` 检索规格，规格正文与标识符写得越明确，检索越稳定。
