### 1.3 提供给模型的上下文

完整提示词见 `artifacts/minimax-prompt.txt`。它包含五部分：

1. **任务描述**；
2. **适用规格**：编号、版本、来源文件与行号、需求正文；
3. **需要修改的文件**：文件全文，保证模型看到的是文件的当前状态；
4. **规格指向的符号**：文件、行号范围、种类与名称；
5. **用于验证的测试**：文件、行号与测试名，以及复用的任务状态。

### 1.4 模型返回与代码差异

| 产物 | 路径 |
| --- | --- |
| 提示词原文 | `artifacts/minimax-prompt.txt` |
| 模型回答与调用信息（模型、输入/输出 token 数、回答原文） | `artifacts/minimax-record.json` |

`artifacts/minimax-record.json` 中的 `minimax` 字段记录了本次调用的模型、
输入 token 数、输出 token 数与回答原文；`diff` 字段是实际应用的差异；
`changed_files` 字段是实际改动的文件。三者与提交的代码差异一一对应。

本次运行使用的差异只改动了一个函数：

```diff
--- a/src/shop/filters.py
+++ b/src/shop/filters.py
@@ -54,5 +54,9 @@ def filter_orders(orders: Iterable[Order], criteria: OrderCriteria) -> list[Order]:
     if criteria.min_amount is not None:
         result = [order for order in result if order.amount >= criteria.min_amount]
     if criteria.customer_tiers:
-        result = [order for order in result if order.customer_tier in criteria.customer_tiers]
+        customer_tiers = set(criteria.customer_tiers)
+        if "premium" in customer_tiers:
+            customer_tiers.remove("premium")
+            customer_tiers.update({"gold", "silver"})
+        result = [order for order in result if order.customer_tier in customer_tiers]
```

模型只修改了规格要求的 `filter_orders`，没有改动 `OrderCriteria`、导入语句、
许可证头或任何测试。

## 2. 数据库查询记录（seekDB）

### 2.1 接入方式

| 项目 | 内容 |
| --- | --- |
| 接入方式 | 嵌入式 seekDB，通过 `pylibseekdb` 启动本地实例，再用 PyMySQL 连接实例暴露的 TCP 端口 |
| 版本 | seekDB `1.4.0.post2`（`SELECT VERSION()` 返回 `5.7.25-OceanBase seekdb-v1.4.0.0`） |
| 数据目录 | `SDDCTX_DB_DIR`，默认 `<root>/.sddctx/seekdb` |
| 表 | `spec_items`、`spec_versions`、`code_symbols`、`test_cases`、`import_runs` |
| 客户端实现 | `sddctx/store.py` |

嵌入式实例在进程内运行，数据写入磁盘目录。进程重启后重新打开同一目录，
之前写入的资料与索引依然可查，模块的单元测试
`tests/test_store_and_retrieve.py::test_the_store_keeps_the_material_across_a_reopen`
覆盖了这个行为。

### 2.2 存储了什么

| 表 | 内容 | 本次运行的条数 |
| --- | --- | --- |
| `spec_items` | 规格条目：编号、标题、需求正文、索引文本、适用范围、版本、来源文件与行号、内容哈希 | 4 |
| `spec_versions` | 规格修订历史：编号、版本、内容哈希、标题、记录时间 | 5 |
| `code_symbols` | 代码符号：标识、文件路径、名称、种类、行号范围、源码片段 | 23 |
| `test_cases` | 测试用例：标识、文件路径、测试名、行号、引用的符号 | 17 |
| `import_runs` | 导入记录：运行编号、时间、各类资料条数 | 每次导入一条 |

### 2.3 实际执行的查询

完整记录见 `artifacts/db-queries.log`，包含每条 SQL 与它的真实返回。核心查询如下。

**导入（写入）**

```sql
INSERT INTO spec_items (spec_id, title, body, search_text, scope, version,
                        source_file, line_start, line_end, content_hash, updated_at)
VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
ON DUPLICATE KEY UPDATE ...
```

**检索规格（全文索引，标识符）**

```sql
SELECT spec_id, MATCH(search_text) AGAINST ('+customer_tiers +premium +gold +silver' IN BOOLEAN MODE)
FROM spec_items
WHERE MATCH(search_text) AGAINST ('+customer_tiers +premium +gold +silver' IN BOOLEAN MODE)
```

返回 `SPEC-FILTER-003`，相关度 `2.978752`。

**检索规格（中文短语）**

```sql
SELECT spec_id FROM spec_items WHERE body LIKE '%为订单筛选增加客户等级分组过滤%'
```

**按适用范围取代码符号与测试**

```sql
SELECT symbol_id, file_path, name, kind, line_start, line_end, snippet
FROM code_symbols WHERE file_path = 'src/shop/filters.py' ORDER BY line_start
```

返回 `OrderCriteria`（32-43 行）与 `filter_orders`（46-67 行）。

**按符号引用取测试**

```sql
SELECT test_id, file_path, name, line_start
FROM test_cases WHERE symbol_refs LIKE '%filter_orders%' OR symbol_refs LIKE '%OrderCriteria%'
ORDER BY file_path, line_start
```

返回 12 个测试，其中包含 `tests/test_filters_tier_groups.py` 的 4 个目标测试。

### 2.4 查询结果如何进入上下文

`artifacts/db-queries.log` 最后一节记录了组装结果：


上下文中的每一条规格都带有来源文件与行号，每一条代码都带有文件与行号范围，
每一条测试都带有文件与行号，因此输出的来源都可以在仓库中直接核对。

### 3.3 读回与复用

模块重启（新的进程）之后：

- `python -m sddctx state show --task-id task-filter-003` 从 Server 读回状态，
  日志见 `artifacts/logs/08-state-show.log`；
- `python -m sddctx context --task ... --task-id task-filter-003` 再次组装上下文时，
  把读回的已完成事项、待办事项和校验结果一并带进上下文，
  结果见 `artifacts/context-reused-state.json` 与 `artifacts/logs/09-context-reused-state.log`。

读回的内容：

| 字段 | 值 |
| --- | --- |
| objective | 为订单筛选增加客户等级分组过滤：`customer_tiers` 中的 `premium` 分组必须展开为 `gold` 与 `silver` |
| done | `changed src/shop/filters.py`、`ran 1 test selection(s)` |
| remaining | （空） |
| checks | `tests/test_filters_tier_groups.py` 状态 `passed` |

完整记录见 `artifacts/powercontext-state.md`。

状态保存在 Server 侧，不依赖模块进程的存活，因此"重启模块后读取并使用状态"
是可以复现的。

## 4. 三项技术的分工

| 技术 | 承担的作用 | 证据 |
| --- | --- | --- |
| MiniMax | 参与本次任务的代码生成与修改 | `artifacts/minimax-record.json`、`artifacts/minimax-prompt.txt`、`artifacts/applied.patch` |
